# Watch 기록 · 실기기 확인 순서

대상: iPhone 16 Pro + Apple Watch Series 9. 프로젝트 최소 대상은 iOS 26 / watchOS 26입니다.
실제 기기의 OS 버전·모델 가용성과 서명은 설치 시 확인하세요.

## 설치

1. 아이폰·워치를 페어링하고 Xcode에서 신뢰·개발자 모드를 준비합니다.
2. iPhone·Watch 타깃을 같은 Developer Team으로 서명합니다. 번들 ID를 바꾸면 WKCompanionAppBundleIdentifier도 일치시킵니다.
3. 양쪽에 업데이트 앱을 설치하고 한 번씩 실행합니다. iPhone 기록 탭에서 기기 내 AI 가용성을 확인합니다.
4. 먼저 iPhone을 가까이에 두고 잠금을 해제한 상태에서 시험합니다. 성공 후 백그라운드·잠금 상태를 나누어 확인합니다.

## 정상 기록

- 워치의 입력창을 눌러 마이크로 “커피 4500원”을 말합니다. 같은 문장을 키보드로도 입력합니다.
- AI로 정리하기를 누릅니다. iPhone에서 분석한 결과가 워치에 표시되는지 확인합니다.
- 금액·수입/지출·분류·메모·날짜를 수정한 뒤 확인하고 저장을 누릅니다.
- 워치의 저장 완료와 대기 메모 제거를 확인합니다. iPhone 내역에 정확히 1건이 생기고 월 합계가 맞는지 확인합니다.
- “어제 커피 4500원”, “용돈 10만원 받음”도 시험합니다. 날짜 기준은 워치에서 기록을 만든 시각입니다.

## 실패·복구

- iPhone이 멀리 있거나 연결되지 않은 상태에서 입력: 메모가 워치에 남아야 합니다. 연결 후 해당 메모를 눌러 재시도합니다.
- 금액 누락·여러 거래·모호한 표현: 자동 저장하지 않아야 합니다. 내용 고치기로 수정하고 다시 분석합니다.
- 미리보기가 있는 상태에서 워치 앱을 종료하고 재실행: 확인할 기록에서 결과를 다시 열 수 있어야 합니다.
- 저장을 누른 직후 연결을 끊어 응답을 잃은 경우: 같은 기록 재시도로 거래가 2건 생기지 않아야 합니다. 이미 저장됐다면 원래 저장된 내용을 유지합니다.
- 연속으로 저장 버튼을 눌러도 처리 중에는 추가 요청을 보내지 않아야 합니다.
- iPhone 앱이 백그라운드이거나 잠긴 상태에서 분석: 성공 여부·소요 시간을 기록합니다. OS·모델 실행 제한으로 실패하면 입력을 유지하고 다시 시도하도록 안내해야 합니다.
- 이전 버전에서 전송 중이던 메모는 iPhone 기록 탭에서 확인하는 기존 흐름으로 남아야 합니다.

## 검증 범위

코드 검사: 요청 크기·형식·초안 검증, 대기 미리보기 재시작 복구, 원문 수정 시 ID/시각 유지,
이전 메모의 전송 방식 유지, 백그라운드 작업 만료 시 정리 1회, 실제 SwiftData 저장·동일 ID 재시도 중복 방지.

실제 기기에서의 연결·받아쓰기·백그라운드 AI·화면 조작은 아직 미검증입니다.
AI는 iPhone의 SystemLanguageModel로 실행하며 클라우드 모델로 대체하지 않습니다.
워치 시스템 받아쓰기는 OS 기능으로 네트워크가 필요할 수 있습니다.
